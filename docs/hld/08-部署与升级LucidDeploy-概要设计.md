# 08 · 部署与升级 LucidDeploy — 概要设计

> 目标：安装与版本升级全流程规范化，支持**主控节点一键命令（lucidctl）**与 **Console 页面向导**两种操作入口；隶属 Master 控制面体系

## 1. 定位与边界

- **做**：制品与版本规范、节点环境基线、一键安装流水线、滚动升级/灰度/回滚、基础设施组件（Kafka/CH/etcd/PG…）升级策略、升级前备份、部署与升级的页面操作。
- **不做**：日常配置变更（Master §5 已有）、节点运行监控（Master 自监控）；k8s 云原生交付（本产品面向裸机/DPDK 场景，暂不做 Helm 化）。

## 2. 组成

| 组件 | 形态 | 职责 |
|---|---|---|
| `lucid-agent` | 每节点常驻 systemd 守护 | 命令通道（与 Master gRPC 双向流）：拉制品、执行白名单脚本、上报结果与日志；节点唯一入口（不依赖 SSH） |
| `lucidctl` | CLI（部署运维人员） | `bootstrap / install / upgrade / rollback / precheck / status / doctor`，在主控节点执行 |
| 制品仓库 | Master 内置 HTTP 服务 | 版本索引 + 全量离线包（SHA256 校验），节点就近拉取 |
| 部署中心 | Console 页面 | 安装向导 / 升级向导 / 节点卡片 / 操作审计，与 CLI 等价 |
| Deploy Engine | Master 内模块 | 流水线状态机（阶段/门禁/暂停点/回滚），驱动 agent 执行 |

## 3. 两类操作流

```
安装：拓扑文件(topology.yml/页面表单) → S0 环境预检 → S1 基础设施 → S2 控制面
      → S3 数据面 → S4 数据初始化 → S5 验收（全程断点续跑、单节点可重试）

升级：上传新版本包 → 兼容矩阵校验 → 预检+自动备份 → Canary 节点 → 按角色滚动
      （排水→替换→门禁→下一台）→ 完成/暂停/回滚
```

## 4. 关键设计决策

| 决策 | 理由 |
|---|---|
| agent 常驻而非 SSH 推送 | 页面可直接操作、无密钥分发；命令白名单+审计，安全边界清晰 |
| 制品全量离线包（bundled 基础设施） | 交付环境多为隔离网；版本受控。支持 external 模式对接现场已有中间件（登记兼容矩阵） |
| 双目录软链 + 只兼容不删除的 schema 迁移 | 秒级回滚二进制；数据向后兼容保证回滚后可用 |
| 每步滚动都有指标门禁 + 自动回滚单节点 | 升级失败影响面控制在单节点，流水线暂停人工决策 |

## 5. 与既有模块关系

- 复用 Master：节点注册/排水（dd/07 §2）、配置版本回滚（§5）、兼容矩阵（§6）；
- 复用 dd/03/04 的健康指标作门禁（Kafka lag、CH replica delay、UDP drop、检测心跳）；
- gobgpd/LucidBGP 升级走其主备切换+resync 机制（dd/06 §3）。

## 6. 关键指标

- 10 节点全新安装 ≤2h（含基础设施）；单节点重装 ≤10min；
- 常规小版本滚动升级 ≤40min，回滚单节点 ≤3min；
- 升级过程数据面损失：仅被升级采集节点排水迁移窗口（<90s/台）。

## 7. 需求映射

用户要求"部署安装、升级版本规范 + 主控一键/页面操作" → 全模块承载；详见 dd/08。
