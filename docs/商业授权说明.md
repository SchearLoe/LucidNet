# LucidNet 商业授权说明（双许可）

LucidNet 采用**双许可（Dual Licensing）**模式，版权所有人为 **SchearLoe**。

## 两种使用方式

| | AGPL-3.0（免费） | 商业许可（付费） |
|---|---|---|
| 适用对象 | 个人学习、研究、内部评估；愿意遵守 AGPL 的开源项目 | 不愿受 AGPL 约束的商业用户、企业产品、闭源集成 |
| 源码修改 | ✅ 必须开源（AGPL-3.0-only，同协议） | ✅ 可闭源 |
| 对外提供服务 | ✅ 但必须向所有用户提供完整衍生源码（网络传染性，AGPL §13） | ✅ 无开源义务 |
| 分发/二次销售 | ✅ 需随附 AGPL-3.0 并开源 | ✅ 按商业合同条款 |
| 商用 | ⚠️ 技术上可行，但必须完全满足 AGPL 义务（含网络服务开源） | ✅ 无额外义务 |

> 简单说：**免费使用的前提是"你的衍生作品也全部按 AGPL-3.0 开源"；做不到这一点（例如闭源商用、闭源 SaaS），必须购买商业授权。**

## 如何获得商业授权

联系版权人洽谈：通过 GitHub 账号 **SchearLoe**（[github.com/SchearLoe](https://github.com/SchearLoe)）发起联系，说明使用场景（部署规模、是否分发、是否托管服务）。商业授权以独立合同为准，可按以下形态报价：按部署节点数、按管理流量规模、或买断式 OEM 嵌入。

## 为什么选 AGPL 而不是 GPL

AGPL-3.0 的第 13 条（Remote Network Interaction）把"网络使用"也纳入传染范围：即使不分发软件、只部署成 Web 服务给用户用，也必须开源衍生代码。这堵住了"SaaS 规避 GPL"的漏洞，是该模式有效的前提。

## 常见问题

- **我内部用、不对外提供服务，需要买授权吗？** 不需要。AGPL 允许纯粹内部使用且无开源义务（不"分发/ conveying"即不触发）。
- **我修改了代码并部署给客户用，需要开源吗？** 是，除非购买商业授权。
- **版权人自己商用受 AGPL 限制吗？** 不受。版权人对自己的作品拥有完整版权，AGPL 只是授予他人的许可条款；版权人可自由地以商业许可再次授权（这正是双许可的原理）。
- **外部贡献者会分走版权吗？** 不会按默认规则分走，但见 `CONTRIBUTING.md`：贡献默认按 AGPL-3.0-only 授权并需授予版权人再许可权利，否则版权人无法对该部分做商业再授权。
- **第三方依赖的兼容性？** 本项目使用的核心依赖（GoFlow2/BSD-3、gobgp/Apache-2.0 等）均为宽松协议，与 AGPL 组合分发合法（保留其原始声明即可，见 `NOTICE.md`）。
