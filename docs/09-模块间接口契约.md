# 09 · 模块间接口契约（唯一权威）

> 版本 v1.0｜2026-10-24｜本文与 `00-公共数据模型与接口规范.md` 共同构成跨模块接口的唯一权威。
> **冲突裁决规则：接口语义在本文与任何模块文档（hld/dd）冲突时，以本文为准；本文未覆盖的，以 00 为准。**

## 0. 契约治理（给并行开发的 agent / 工程师）

1. 任何跨模块接口变更：先改本文（+00），评审合入后各模块才可跟进实现；禁止先改实现后补契约。
2. proto / DDL 演进规则：字段与列**只增不改不删**（废弃标 deprecated，保留 ≥2 个 MINOR 版本）；Kafka 分区只增不减；topic/key 语义变更视为破坏性变更（需 MAJOR）。
3. 每个接口有唯一"属主模块"（下表标 ★），属主负责定义与兼容性，其他模块是消费方。

## 1. 接口总览

```
Broker ──UDP原流──► Collector ──flows.raw──► [Analytics组] ──flows.aggr.minute──► [Inserter] ──► CH
                        │        │                 │      └─attacks.minutes──► [Inserter] ──► CH
                        │        │                 │      └─alarms──────────► LucidBGP / 网关WS / [Inserter]
                        │        │                 └─bgp.mitigations 消费（处置回执→FSM）
                        │        └─flow.templates（自身恢复）
                        └─RibNameLookup(gRPC:9131)◄── RIB Feeder ◄── gobgpd
etcd（配置/分配表/zone）: Master★ 写，Broker/Collector/Analytics watch
PG（配置权威库）: Master★ DDL 属主；业务数据各模块分区读写（§7）
REST /api/v1/*: 全部经网关（lucid-gateway★），路由到提供方（§6）
```

## 2. Kafka 契约（★属主：Collector 对 flows.raw / flow.templates / snmp.* / syslogs.*；Analytics 对 flows.aggr.minute / attacks.minutes / alarms；RIB Feeder 对 bgp.updates；LucidBGP 对 bgp.mitigations）

Topic 表见 00 §3（key/消息/生产者→消费者/参数），补充实现约束：

| Topic | 信封消息定义（proto/lucidnet/v1/envelope.proto） |
|---|---|
| `flows.aggr.minute` | `AggrMinuteBatch { repeated AggrRow rows=1; uint64 batch_id=2 }`，AggrRow = aggr_minute 表列 + `-State` 聚合中间态 |
| `attacks.minutes` | `AttackMinuteBatch { repeated AttackMinute rows=1; uint64 batch_id=2 }` |
| `alarms` | `AlarmEnvelope { oneof payload { Alarm alarm=1; AttackEvent attack=2 } }` |
| `flow.templates` | `TemplateRecord { exporter, obs_domain, template_id, body, version, ts }` |
| `bgp.mitigations` | `MitigationEvent { mitigation_id, action, prefix, expire_at, result, attack_id, ts }` |

- 序列化：proto + lz4；producer `linger=50ms, batch≥64KB`；consumer 组名规范 `<module>.<purpose>`（如 `analytics.detect`、`storage.inserter.flows`、`bgp.alarmlink`、`gateway.ws`），**组名即接口，新增消费组需登记本文**。
- 新增消费组登记（2026-10-25 裁定）：`master.heartbeat` —— `cluster.heartbeat` 的 Master 副本消费（可选通道）；shared 常量 `GroupMasterHeartbeat` 已同步。
- 幂等：Inserter 侧按 `batch_id` + PG `export_batches` 去重；Analytics 侧天然幂等（累加语义 + 迟到丢弃规则见 dd/03 §8）。
- Broker 转发引擎 `kafka` 目的地（2026-10-25 裁定）：登记为正式能力（opt-in，由转发规则配置启用），消息 key 与 `shared.FlowKey` 一致；归属裁定：`flows.raw` 属主生产者仍为 Collector（节首 ★ 不变），Broker 仅按规则选择性生产，**禁止全量旁路双写**。

## 3. FlowRecord 关键字段语义（★属主：Collector；Analytics/Inserter/Console 为消费方）

| 字段 | 语义裁定 |
|---|---|
| `zone_id` | 采集侧 Zone 匹配命中结果，**一条记录只标一个客户域**；0=未命中。匹配面 `zone_match=dst|src`（默认 dst），禁止 both |
| `zone_side` | 1=dst 命中 / 2=src 命中 / 0=未命中。**方向换算唯一依据**：1→客户视角 in（流入客户），2→out（客户发出）；下游不得用 ifIndex 自行推断方向 |
| `if_role` | bit0=入接口 boundary，bit1=出接口 boundary；unknown 按 boundary。互联过滤规则（`internal_exclude=true` 默认）：**仅 in 与 out 均为 internal（两位均 0）时丢弃**——纯互联链路流量；boundary↔internal（正常客户-骨干路径）保留 |
| `sample_rate` | 全链路累计采样率倒数（exporter × R1 再采样），展示侧加权还原 |
| `in_if/out_if` | SNMP ifIndex 命名空间；与资产库 interfaces 对齐，不一致设备走 manual_if_map |

## 4. gRPC 契约

| 服务 | 提供方 | 消费方 | 方法 | 端口 |
|---|---|---|---|---|

- JWT claims（2026-10-25 裁定）：claims 在 `{uid,name,tenant,roles,exp}` 基础上增 `perms`（权限码数组，`<domain>:<action>`，可含通配）；由 Master 登录/refresh 时从 RBAC 角色展开签发；资源网关（Console）直接校验 token 内 `perms`，不再回查 RBAC；角色变更经 refresh 生效。

## 5. etcd 键空间（★属主：Master 写；各模块只读 watch；结构 = protobuf/JSON + 单调 version）

| 键 | 消费方 | 内容 |
|---|---|---|
| `/lucid/assign/flow` | Broker、Collector | exporter→collector 一致性哈希分配表快照 |
| `/lucid/forward/rules` | Broker | R1 转发规则（含 exporter_groups 展开） |
| `/lucid/zones` | Collector（zone 匹配树）、Analytics | Zone 配置（PG 同步） |
| `/lucid/config/collector/{node}` | Collector | 端口/采样登记表/命名正则/RIB 快照指针 |
| `/lucid/config/analytics` | Analytics | internal_exclude、检测阈值覆盖、维护静默 |
| `/lucid/leader` | Master、Analytics Leader | 选主 |

变更生效 SLA：写后 ≤2s 全节点可见（dd/02 §3.3 同口径）。

- 配置值信封（2026-10-25 裁定）：`/lucid/zones`、`/lucid/forward/rules`、`/lucid/config/analytics`、`/lucid/config/collector/{node}` 四个配置键的值统一为信封结构 `{"version","updated_at","data"}`（Master 已按此实现，见 `master/internal/config`）；Collector 等消费方在 watch 入口须先解信封取 `data`（Collector 现有裸数组解析待适配，M1 对接时修正）；`/lucid/assign/flow`、`/lucid/leader` 不适用信封。
- shared 镜像（2026-10-25 裁定）：本节键已镜像为 `shared/etcdkeys.go` 常量；本文 §5 为唯一权威。

## 6. REST API 归属（全部经 `lucid-gateway` ★，路由到提供方模块）

| 路由前缀 | 提供方 | 说明 |
|---|---|---|
| `/api/v1/flows/search`、`/api/v1/export/jobs` | Storage（QueryService/ExportService） | R6 明细查询、R5 异步导出 |
| `/api/v1/attacks*`、`/api/v1/topn*`、`/api/v1/baseline*` | Storage（读 CH/Redis）+ Analytics（实时状态） | 攻击中心/矩阵页数据 |
| `/api/v1/alarms` | Storage | 告警历史读取（告警历史落库 CH）；Console 经网关转发（2026-10-25 裁定） |
| `/api/v1/reports*` | Console 报表服务（lucid-reporter） | R8 |
| `/api/v1/admin/*`、`/api/v1/auth/*` | Master | 节点/设备/Zone/规则/用户/RBAC/版本 |
| `/api/bgp/*`（反代） | LucidBGP（含既有 `POST /api/alarms` 保留直调） | R9；SSO `POST /api/bgp/sso` 一次性 token |
| `/api/v1/stream/*`（WS） | 网关自身 | 数据源 = 网关消费 `alarms`/`bgp.mitigations` + 轮询 Redis `rt:*`（TopN） |

补充裁定（2026-10-25）：

- Redis 实时键：统一 `rt:*` 前缀（本节 `/api/v1/stream/*` 数据源口径与 00 §6 为准）；dd/03 中 `topn:{dim}:{ts}` 写法作废（dd 文档不回改，以本文为准）。
- 查询时间参数单位：`/api/v1/flows/search`、`/api/v1/export/jobs`、attack minutes 等跨模块查询 API 的时间参数统一为 epoch 秒（对齐 ClickHouse `time` 列秒精度）。
- WS 报文信封：`/api/v1/stream/{topic}` 下行报文统一信封 `{"topic","type","zone_id","ts_ms","data"}`；订阅参数 `?access_token=&zone_id=`（Console 已按此实现）。

## 10. 并行开发任务包边界建议（给分派 agent）

- **接口冻结**：proto 文件（`proto/lucidnet/v1/`）与 topic 组名先行建仓合入，各 agent 从此骨架起步；
- **联调桩**：跨模块依赖用可替换桩（如 Collector 的 RibNameLookup 客户端 ↔ Analytics 的 flows.raw 消费），契约以本文 §2/§4 的消息与方法签名为准；
- **变更流程**：agent 发现契约不合理 → 提 Issue 改本文，不得在各自模块内私改接口。
