# 00 · 公共数据模型与接口规范

> 版本 v0.1｜被所有模块设计文档引用｜变更需评审
> 覆盖需求：R2（Zone 模型）、R3（IPv4/IPv6）、R5（攻击模型/导出格式）、R6（明细查询语义）

## 1. 统一地址表示（R3）

- 进程内/线路上：地址一律 128bit（`bytes(16)`）。IPv4 以 `::ffff:a.b.c.d` 映射存储，函数库提供 `IsV4()/ToV4()`。
- 判断依据写显式字段 `ip_version`（写者填充，不靠推导），避免查询层歧义。
- ClickHouse 中 `src_ip/dst_ip` 使用 `IPv6` 类型（CH 对 v4-mapped 存储无膨胀）；展示层按 `ip_version` 决定显示格式。

## 2. 核心 protobuf（仓库 `proto/lucidnet/v1/`）

### 2.1 FlowRecord（flows.raw 消息体）

```protobuf
syntax = "proto3";
package lucidnet.v1;

message FlowRecord {
  // —— 时间（流开始/结束，毫秒）
  int64  time_start_ms = 1;
  int64  time_end_ms   = 2;
  // —— 来源
  string exporter      = 3;   // exporter IP（文本）
  uint32 device_id     = 4;   // 资产库设备ID（SNMP 对齐，0=未知）
  uint32 in_if         = 5;   // ifIndex（SNMP 命名空间）
  uint32 out_if        = 6;
  // —— 五元组
  bytes  src_ip = 7;          // 16B，v4 用 ::ffff: 映射
  bytes  dst_ip = 8;
  uint32 src_port = 9;
  uint32 dst_port = 10;
  uint32 proto    = 11;       // IP 协议号
  uint32 ip_version = 12;     // 4/6（R3）
  // —— 计量
  uint64 packets = 13;
  uint64 bytes   = 14;
  uint32 tcp_flags = 15;      // 位掩码
  uint32 tos        = 16;
  uint32 sample_rate = 17;    // exporter 采样率倒数（1=全采）
  // —— 富化（采集侧完成）
  uint32 src_as = 20;  uint32 dst_as = 21;
  bytes   bgp_next_hop = 22;
  uint32  src_geo = 23;  uint32 dst_geo = 24;   // GeoIP 编码
  uint32  app_id  = 25;                          // 端口/协议→应用映射
  int32   zone_id = 26;                          // 客户域（R2），0=未命中
  uint32  if_role = 27;                          // 入/出接口角色位图：bit0 in=boundary, bit1 out=boundary
}
```

字段只增不改；版本化演进（proto 包名带 v1）。

### 2.2 Zone（客户域，R2）

```protobuf
message ZoneSpec {            // etcd/PG 中配置，采集侧缓存
  int32  id = 1;
  string name = 2;
  string tenant = 3;
  repeated IpEntry ips = 4;   // ≤1000 条/客户
  repeated uint32 boundary_ifs = 5;  // 可选绑定边界接口（设备ID+ifIndex 二元组见PG模型）
  int32  policy_id = 6;       // 检测策略模板
}
message IpEntry {
  bytes prefix = 1;           // 16B 地址
  int32 mask_len = 2;         // v4:0-32（地址按v4填4B？统一16B+mask_len按族） , v6:0-128；单IP=全长度掩码
}
```
> 单客户 1000 IP、集群 300 客户起步（R2 下限），模型不设硬上限，检测引擎按 1,000 客户内存预算设计（见 dd/03 §4.6）。

### 2.3 攻击模型（R5）

```protobuf
message AttackEvent {         // 写 ClickHouse attacks + Redis 实时镜像
  string attack_id = 1;       // ULID
  int32  zone_id = 2;
  string zone_name = 3;
  uint32 attack_type = 4;     // 枚举：SYN_FLOOD/UDP_FLOOD/ACK_FLOOD/ICMP_FLOOD/
                              //       REFLECTION/SWEEP(扫段R7)/ANOMALY(波动R7)/UNKNOWN
  string target_prefix = 5;   // 受害前缀/关键目标（文本）
  int64  start_ms = 6;  int64  end_ms = 7;
  int64  peak_bps = 8;  int64  peak_pps = 9;
  float  confidence = 10;     // 0-1
  repeated string top_sources = 11;   // 证据：Top 源（≤100）
  string evidence_json = 12;  // 特征快照（端口分布/flag比/熵…）
  uint32 status = 13;         // 1候选 2确认 3处置中 4已缓解 5误报关闭
  string mitigation_id = 14;  // LucidBGP 处置关联（R9）
}
message AttackMinute {        // 分钟级攻击详情（R5），每攻击每分钟一行
  string attack_id = 1;
  int32  minute_epoch = 2;    // 分钟对齐
  int64  bps_in = 3;  int64  pps_in = 4;
  int64  bps_out = 5; int64  pps_out = 6;
  uint64 new_flows = 7;
  float  syn_ratio = 8;  float  udp_ratio = 9;
  repeated string top_sources = 10;
  repeated uint32 top_ports = 11;
}
```

## 3. Kafka Topic 规范

| Topic | Key | 说明 |
|---|---|---|
| `flows.raw` | `zone_id(4B)+exporter` | FlowRecord；分区 ≥96；lz4；保留 24h |
| `flows.aggr.minute` | 维度哈希 | 分钟聚合结果（总线副本，供第三方/审计） |
| `bgp.updates` | router | RIB 增量事件（RIB Feeder 产出） |
| `bgp.mitigations` | — | LucidBGP 处置动作/到期撤销事件（R9，回执闭环） |
| `snmp.ifcounters` | device | 接口计数器（VM 另行直写，本 topic 供审计/对账） |
| `alarms` | zone_id | Alarm/AttackEvent 事件流 |
| `cluster.heartbeat` | node | 节点心跳（etcd 为主，此为审计副本） |

分区数 = 采集节点核数总和 ×1.5 向上取 2 的倍数；所有消息 schema 登记 `docs/schema-registry.md`。

## 4. ClickHouse DDL（存储卷策略见 dd/04）

```sql
-- 明细（R6：15天，冷热分层）
CREATE TABLE flows_raw ON CLUSTER lucid
(
  time_second  DateTime,
  time_ms      UInt16,
  exporter     LowCardinality(String),
  device_id    UInt32,  in_if UInt32,  out_if UInt32,
  src_ip IPv6,  dst_ip IPv6,
  src_port UInt16, dst_port UInt16, proto UInt8, ip_version UInt8,
  packets UInt64, bytes UInt64, tcp_flags UInt8, tos UInt8, sample_rate UInt32,
  src_as UInt32, dst_as UInt32, app_id UInt32, zone_id Int32, if_role UInt8,
  INDEX bf_src src_ip TYPE bloom_filter GRANULARITY 4,
  INDEX bf_dst dst_ip TYPE bloom_filter GRANULARITY 4
)
ENGINE = ReplicatedMergeTree('/ch/lucid/{shard}/flows_raw','{replica}')
PARTITION BY toYYYYMMDD(time_second)
ORDER BY (time_second, exporter, zone_id, in_if, out_if, proto, dst_port, src_ip)
TTL time_second + INTERVAL 3 DAY TO VOLUME 'hot',
    time_second + INTERVAL 15 DAY TO VOLUME 'cold'
SETTINGS storage_policy='hot_cold', index_granularity=8192;
-- 15 天到期删除（R6）；若开启降采样，写入端提前抽稀

-- 分钟聚合（13 个月）
CREATE TABLE aggr_minute ON CLUSTER lucid (
  minute DateTime, exporter LowCardinality(String),
  device_id UInt32, in_if UInt32, out_if UInt32, direction UInt8,
  zone_id Int32, src_as UInt32, dst_as UInt32,
  proto UInt8, dst_port UInt16, app_id UInt32,
  bytes AggregateFunction(sum, UInt64),
  packets AggregateFunction(sum, UInt64),
  flows  AggregateFunction(count)
) ENGINE = ReplicatedAggregatingMergeTree(...)
PARTITION BY toYYYYMM(minute)
ORDER BY (minute, exporter, in_if, zone_id, proto, dst_port)
TTL minute + INTERVAL 13 MONTH;
-- aggr_hour 同构，TTL 3 年；物化视图从 flows_raw 滚动（dd/04 §3）

-- 攻击（R5）
CREATE TABLE attacks (...)          ENGINE = ReplicatedMergeTree
PARTITION BY toYYYYMMDD(start_ms/1000) ORDER BY (zone_id, start_ms) TTL 1 YEAR;
CREATE TABLE attack_minutes (...)   ENGINE = ReplicatedMergeTree
PARTITION BY toYYYYMM(minute) ORDER BY (attack_id, minute) TTL 6 MONTH;
```

## 5. PostgreSQL 配置库（Master 管辖）

核心表（详细 DDL 见 dd/07）：`devices / interfaces(role,role_source) / exporters / zones+zone_ips / detect_policies / forward_rules(R1) / users / roles / reports(R8) / export_jobs(R5) / mitigations(R9 镜像)`。

`interfaces.role`：`boundary|internal|unknown`，`role_source`：`manual|lldp|igp|naming|default`（识别算法见 dd/02 §5）。

## 6. REST API 约定

- 前缀 `/api/v1`，JWT Bearer（Master 签发），多租户字段隔离；分页 `?page=&page_size=`，响应 `{code,msg,data}`。
- 长查询/导出一律走**异步任务**：`POST /export/jobs` → `{job_id}` → `GET /export/jobs/{id}`（状态/进度/下载URL）。产物落 MinIO，链接 24h 有效（R5/R6 导出）。
- WebSocket/SSE：`/api/v1/stream/alarms|attacks|events`（攻击与告警实时推送）。

## 7. 原始日志文本格式（R5 导出，"数据流转格式化文本"）

```
# LucidNet flow export | zone=客户A(101) | window=2026-10-24T13:05:00+08:00/13:15:00
# start              end                proto src                    dst                     pkts  bytes   flags if_in/if_out sample
2026-10-24 13:05:01.123 13:05:03.400   TCP   2001:db8::1:44321      2001:db8:5::80:443      120   86400   .A.S. 12/15        1
2026-10-24 13:05:01.200 13:05:01.350   TCP   ::ffff:1.2.3.4:55555   ::ffff:5.6.7.8:80       10    6400    SYN   3/4           100
```

- 编码 UTF-8；分隔符：定宽多空格（对齐）或 `--format=csv|jsonl|text`（默认 text 如上）。
- 字段顺序与过滤条件随任务参数持久化在导出文件头注释，满足取证可追溯。

## 8. 度量与字段命名约定

- 带宽一律 bps、包速率 pps、方向以"客户视角 in=流入客户/out=流出客户"为准（分析层换算，见 dd/03 §2.3）。
- 所有采样数据展示时按 `sample_rate` 加权还原并标注"估算值"。
